# 상자 이용 기록 — Minecraft Bedrock

상자에 넣거나 가져간 아이템·수량·시간을 **플레이어별로 조회**하고, 상자를 **소유자 외 파괴와 폭발로부터 보호**하는 행동 팩입니다. 엑스레이 탐지 기능은 포함하지 않습니다.

**중요: 기본 상자 인벤토리 대신 버튼과 수량 선택으로 구성한 전용 보관함 화면을 사용합니다.** BE 안정판 Script API는 기본 상자 화면의 모든 아이템 이동과 행위자를 알려주는 이벤트를 제공하지 않습니다. 기본 화면을 추측해서 감시하는 대신 이 팩이 처리한 입출고만 기록합니다.

## 설치와 사용

[설치 파일 다운로드: ChestHistory-1.1.0.mcpack](https://github.com/twodaysfriend-dot/Addon/raw/refs/heads/main/downloads/ChestHistory-1.1.0.mcpack)

다운로드한 파일을 Minecraft로 열고 월드의 행동 팩에서 활성화하세요. 설치 파일은 `downloads/`에도 보관합니다.

대상은 **BE 1.21.90 이상, 안정판 `@minecraft/server` 2.0.0 / `@minecraft/server-ui` 2.0.0**입니다. 최신 버전의 호환성과 실제 게임 동작은 아래 수동 검증이 필요합니다. 프리뷰·베타 API는 사용하지 않습니다.

1. 월드를 백업합니다.
2. `dist/ChestHistory-1.1.0.mcpack`을 Minecraft로 열어 가져옵니다.
3. 해당 월드의 **행동 팩 → 내 팩 → 상자 이용 기록 → 활성화**를 선택합니다. 리소스 팩은 필요 없습니다.
4. 일반 상자 또는 덫 상자를 누릅니다. **가져가기 / 내용 보기** 또는 **넣기**를 누르고 아이템과 수량을 선택합니다. 1개짜리 아이템은 선택 즉시 이동합니다.
5. 월드 소유자/운영자는 명령어를 실행할 수 있는 권한으로 관리자 태그를 부여합니다. 이름에 공백이 있으면 따옴표를 사용합니다.

   ```mcfunction
   /tag "관리자닉네임" add chestlog.admin
   ```

6. 관리자는 상자 화면의 **이 상자 기록 조회**를 누르거나, **막대기를 들고 웅크린 상태로 상자를 사용**합니다. 게임패드는 웅크리기 + 사용, 터치는 해당 동작으로 이용합니다.
7. 기록 화면에서 **플레이어 이름**을 선택하면 그 사람의 입출고 시간·아이템·수량이 나옵니다. 열기만 한 플레이어는 목록에 나오지 않습니다.
8. **전체 상자 기록 목록**에서 다른 상자나 철거된 상자의 좌표를 선택해 기록을 조회할 수 있습니다. 목록은 아무 상자의 관리자 메뉴에서 열 수 있습니다.

관리자 권한 해제:

```mcfunction
/tag "관리자닉네임" remove chestlog.admin
```

큰 상자를 만들거나 상자에 블록을 붙일 때는 **블록 아이템을 들고 웅크린 상태로 설치**합니다. 이 동작은 일반 블록 설치로 처리하여 전용 화면을 열지 않습니다.

전용 화면에서는 기본 상자의 드래그·Shift 클릭·빠른 이동 UI를 제공하지 않습니다. 상자 뚜껑 애니메이션, 가려진 뚜껑의 개방 제한, 덫 상자의 열림 레드스톤 신호도 기본 상자 UI와 같지 않습니다. 기존 상자 회로가 있는 월드에서는 먼저 별도 테스트 월드를 사용하세요.

## 상자 보호 규칙 (1.1.0)

- **신규 상자:** 플레이어가 설치하면 이름과 플레이어 ID를 월드에 소유자로 저장합니다. 소유자 또는 `chestlog.admin` 태그를 가진 관리자만 부술 수 있습니다. 다른 플레이어는 크리에이티브 상태에서도 파괴를 거부합니다.
- **기존 상자·소유자 미등록 상자:** 누가 설치했는지 과거 정보를 알 수 없으므로 **관리자만 파괴할 수 있습니다.** 먼저 여는 사람이 소유자가 되는 방식은 사용하지 않습니다.
- **소유자 지정:** 관리자가 상자를 열고 **상자 소유자 지정 → 온라인 플레이어 선택 → 지정 확인**을 하면 큰 상자 양쪽까지 선택한 사람의 소유로 바뀝니다. 기존 상자도 이 기능으로 등록합니다.
- **큰 상자:** 양쪽 모두 같은 플레이어 소유여야 그 플레이어가 부술 수 있습니다. 소유자가 섞였거나 한쪽이 미등록이면 관리자만 부술 수 있습니다. 관리자 지정으로 양쪽 소유권을 정리할 수 있습니다.
- **폭발:** `beforeEvents.explosion`의 파괴 대상에서 일반 상자·덫 상자를 제외합니다. TNT·크리퍼 등 이 이벤트로 전달되는 폭발에 적용하며 소유자 등록 여부와 무관합니다. 주변의 다른 블록 파괴나 엔티티 피해까지 막는 기능은 아닙니다. 대상 목록 확인에 실패하면 해당 폭발을 취소합니다.
- **피스톤:** 안정판 API에서는 피스톤 이동을 취소하지 못합니다. 이동에 연관된 원래/도착 좌표의 소유권을 무효화하여 잘못된 소유자로 파괴 권한이 이어지는 것을 방지합니다. 이동 후 관리자가 소유자를 다시 지정해야 할 수 있습니다. 입출고 기록은 이전 좌표에 남습니다.
- 소유자는 닉네임 대신 플레이어 ID로 판정하므로 닉네임만 같다고 파괴 권한을 주지 않습니다. 정상 파괴 후 그 좌표의 소유권은 지우며 재설치하면 새 설치자가 소유자가 됩니다.
- 관리자 명령어(`/setblock`, `/fill` 등), 다른 팩의 직접 블록 변경, 팩을 끈 동안의 변경은 이 보호의 적용 범위 밖입니다. 소유권은 동적 속성으로 보존하며 월드를 저장해야 디스크에 반영됩니다.

## 기록에 포함되는 정보

- 열기만 하거나 화면을 닫은 경우, 수량 선택 취소, 아이템을 이동하지 않은 경우는 일반 기록에 남기지 않습니다. 이전 1.0.0 버전의 열람 요청 기록도 조회에서 숨깁니다.
- **넣음 / 가져감:** 플레이어 이름·ID, 처리 시간, 아이템 ID, 수량, 사용자 지정 이름, 설명, 손상도, 인챈트, 아이템 동적 속성 등. 조회 화면에는 핵심 정보와 인챈트를 표시합니다. 나머지 메타데이터도 월드 기록에 저장합니다.
- 시간은 UTC로 저장하고 조회할 때 **한국 표준시(KST)**로 표시합니다.
- 같은 큰 상자의 두 쪽은 하나의 기록을 공유합니다. 합치거나 분리한 뒤에는 현재 상자 좌표와 겹치는 이전 기록도 함께 조회합니다. 철거·재설치한 같은 좌표는 이전 기록을 이어 사용합니다.
- 기록은 팩의 고정 header UUID에 속한 **월드 동적 속성**으로 저장합니다. 월드가 저장되어야 디스크에 반영됩니다. 업데이트할 때 `manifest.json`의 header UUID를 바꾸지 마세요. 팩을 끈 동안의 행위는 기록되지 않습니다.

보존 한도는 **좌표별 최근 120건 또는 UTF-8 28,000바이트 중 먼저 도달하는 한도**입니다. 아이템 메타데이터가 많으면 120건보다 적게 보존됩니다. 오래된 기록은 순서대로 삭제하며 삭제 건수를 보여 줍니다. 최대 1,024개 기록 상자를 보존하고, 한도에 도달하면 새 좌표 상자의 전용 이용을 거부합니다. 영구 무제한 감사 로그나 외부 DB는 제공하지 않습니다.

## 정확도와 적용 범위

- 이 팩이 처리한 UI 입출고만 행위자를 기록합니다. **호퍼·드로퍼·상자 파괴·폭발·명령어·다른 애드온이 바꾼 아이템은 플레이어 입출고로 기록하지 않습니다.** 파괴 방지는 아래 규칙으로 적용합니다. 아이템 이용 자체는 소유자 전용으로 잠그지 않으며, 다른 플레이어의 정상 UI 입출고도 기록합니다.
- 일반 상자와 큰 상자, 덫 상자만 지원합니다. 엔더 상자, 통, 셜커 상자, 상자 달린 이동수단은 지원하지 않습니다.
- 여러 플레이어가 같은 슬롯을 선택하면 처리 직전에 실제 아이템과 수량을 다시 검증합니다. 공간 부족, 멀어진 플레이어, 변경된 아이템은 이동을 거부합니다. 아이템은 복제한 스택으로 이동해 이름·인챈트 등을 유지합니다.
- 일반 조회는 성공한 입출고만 플레이어 ID별로 묶어 최신순으로 표시하고, 플레이어 선택 후 시간·아이템·수량을 보여 줍니다. 플레이어별 넣기/가져가기 횟수도 표시합니다. 실패·미확정 기록은 별도의 **미확정·오류 기록** 화면에만 보입니다.
- 이동 전에 **미확정 기록**을 먼저 저장하고, 실제 처리 후 완료로 바꿉니다. 사전 기록 저장에 실패하면 이동하지 않습니다. 도중 서버 강제 종료, 완료 저장 실패, 컨테이너 복구 실패가 생기면 미확정/복구 미확정 기록이 남을 수 있습니다. **이 기록을 이동 완료로 해석하면 안 됩니다.** 월드 저장과 아이템 이동을 하나의 디스크 트랜잭션으로 묶는 보장은 없습니다.
- 다른 상자 UI/보호 애드온과의 호환성은 별도 검증이 필요합니다. 이 팩은 다른 애드온의 보호 정책을 통합하지 않습니다. 관리 태그를 가진 사용자는 모든 보존 상자의 기록을 볼 수 있습니다.

## 개발과 패키징

Node.js 24, npm, Python 3를 사용합니다. 저장소에서 실행합니다.

```sh
npm --cache /workspace/.npm-cache ci
npm run check
npm test
npm run build
```

일반 PC에서는 캐시 옵션 없이 `npm ci`도 가능합니다. `build`는 API 선언 기반 JavaScript 타입 검사, 매니페스트 검사, 자동 테스트 후 `.mcpack`을 만들고 ZIP 무결성을 검사합니다. `@minecraft/server` npm 패키지는 타입 선언이며 게임 서버 자체가 아닙니다.

파일 구조:

- `behavior_pack/manifest.json`: 팩 ID와 API 버전
- `behavior_pack/scripts/main.js`: 상자 상호작용, 전용 화면, 월드 저장 및 관리자 조회
- `behavior_pack/scripts/core.js`: 아이템 이동 계획·복구 및 보존 한도 로직
- `tests/`: 순수 로직 테스트와 모의 Bedrock API를 통한 실제 핸들러 테스트
- `tools/`: 검증 및 패키징 도구

## 검증 상태와 실제 게임 확인 절차

이 클라우드 환경에서는 **타입·매니페스트 검사, 자동 테스트 39개, ZIP 패키징을 검증**했습니다. 테스트는 모의 컨테이너와 API를 사용하며 **Minecraft 게임 실행 검증은 아직 하지 않았습니다.** 배포 전 테스트 월드에서 다음을 확인하세요.

1. 팩 가져오기와 활성화 후 콘텐츠 로그에 스크립트 오류가 없는지 확인합니다.
2. 일반 상자에서 다이아몬드 10개 중 4개를 넣고 2개를 꺼냅니다. 상자에 2개, 플레이어에게 8개가 남고 관리자 기록에 정확한 사용자·수량·KST 시간이 표시되는지 확인합니다.
3. 두 플레이어가 같은 스택을 동시에 가져가기를 시도해 전체 아이템 수가 보존되는지 확인합니다. 가득 찬 인벤토리와 상자에서도 실패 시 손실이 없는지 확인합니다.
4. 이름·인챈트가 있는 손상된 장비를 넣고 꺼내 속성과 기록을 비교합니다.
5. 일반 플레이어의 막대기 조회가 거절되고 관리자만 조회되는지 확인합니다. 큰 상자의 양쪽 기록도 비교합니다.
6. 월드를 저장하고 종료한 뒤 다시 실행하여 기록이 유지되는지 확인합니다. 상자 철거 후 다른 상자의 전체 목록에서도 이전 기록을 조회합니다.
7. 이용 중 거리 이동, 상자 파괴, 큰 상자 합치기/분리, 모바일·게임패드 조작을 확인합니다.
8. 호퍼 이동은 플레이어 이름으로 기록되지 않는지 확인합니다. 기본 레드스톤/뚜껑 동작이 필요한 구조는 전용 화면 방식과 맞는지 확인합니다.

9. 상자를 열기만 하거나 수량 선택을 취소했을 때 기록에 나타나지 않는지 확인합니다. 두 플레이어가 각각 입출고한 뒤 이름별로 선택해 기록이 섞이지 않는지 확인합니다.
10. A가 설치한 상자를 A와 관리자는 부술 수 있고 B는 생존·크리에이티브 모두에서 부술 수 없는지 확인합니다. 기존 미등록 상자도 B의 파괴를 거부하고 관리자 지정 후 새 소유자만 부술 수 있는지 확인합니다.
11. 큰 상자의 양쪽 소유자가 같을 때와 다를 때 파괴 권한을 확인합니다. 소유자 지정 확인 중 관리자 태그를 제거한 경우 변경이 거부되는지 확인합니다.
12. TNT·크리퍼·침대·리스폰 정박기 등 사용할 월드의 폭발을 테스트해 상자와 내용물이 유지되고 주변의 다른 블록만 영향을 받는지 확인합니다. 피스톤으로 옮긴 상자는 관리자 재지정 절차도 확인합니다.
