# Minecraft Bedrock 애드온

- [상자 이용 기록 1.4.0 다운로드](https://raw.githubusercontent.com/twodaysfriend-dot/Addon/main/downloads/ChestHistory-1.4.0.mcpack)
- [나히아 개성 1.3.0 다운로드](https://raw.githubusercontent.com/twodaysfriend-dot/Addon/main/downloads/MHAQuirks-1.3.0.mcaddon)

두 팩은 Minecraft Bedrock 1.21.90 이상에서 각각 설치할 수 있습니다. 둘 다 사용하려면 각 `.mcpack`을 가져온 뒤 월드의 **행동 팩 → 내 팩**에서 두 팩을 활성화하세요.

기존 통합판 1.3.0을 사용했다면 월드를 백업하고 상자 이용 기록을 1.4.0으로 업데이트하세요. 1.4.0은 기존 상자 기록과 소유권을 이어서 사용합니다. 월드를 다시 열기 전에 나히아 개성도 활성화하면 기존 스테인의 검을 계속 사용할 수 있습니다.

## 상자 이용 기록

상자를 **바닐라 인벤토리 화면 그대로** 사용하면서 아이템 수량 변화를 관찰하고, 관리자에게 플레이어별 기록을 보여 주는 행동 팩입니다. 설치자 외 파괴와 폭발로부터 상자를 보호합니다.

### 설치와 조작

대상: **BE 1.21.90 이상 / 안정판 `@minecraft/server` 2.0.0, `@minecraft/server-ui` 2.0.0**. 프리뷰·베타 API와 리소스 팩은 필요 없습니다. 실제 게임 호환성은 테스트 월드에서 확인해야 합니다.

1. 월드를 백업하고 `.mcpack` 파일을 Minecraft로 열어 가져옵니다.
2. 월드의 **행동 팩 → 내 팩 → 상자 이용 기록**을 활성화합니다. 이전 버전에서 업데이트할 때는 같은 UUID의 1.4.0 팩으로 교체하고 월드를 다시 실행합니다.
3. **일반 우클릭/사용:** Minecraft 기본 상자가 열립니다. 드래그, 빠른 이동, 상자 뚜껑과 덫 상자 회로 등은 게임이 처리합니다. 이 팩은 우클릭을 취소하거나 별도 보관함 화면을 열지 않습니다.
4. 관리자는 명령어로 태그를 부여받습니다.

   ```mcfunction
   /tag "관리자닉네임" add chestlog.admin
   ```

5. **관리자만 웅크리고 막대기를 주 손에 든 상태로 상자를 좌클릭(공격)**하면 기록 화면이 나옵니다. 모바일·게임패드는 사용/상자 열기가 아니라 **공격/블록 때리기** 동작입니다. 이 조회 동작으로 상자를 부수지 않도록 크리에이티브 즉시 파괴도 취소합니다.
6. 플레이어 이름을 선택하면 그 사람의 시간·아이템·수량을 확인합니다. **미확인·오류 기록**은 플레이어를 확정할 수 없는 수량 변화와 이전 버전의 오류 기록을 따로 보여 줍니다.
7. 같은 화면의 **전체 상자 기록**에서 철거된 상자의 보존 기록을 조회할 수 있습니다. **상자 소유자 지정**에서는 온라인 플레이어를 선택하고 확인하여 소유자를 지정합니다.

우클릭, 웅크리지 않은 클릭, 막대기 없는 클릭, 일반 플레이어의 클릭으로는 조회 UI가 열리지 않습니다. 일반 파괴는 아래 보호 규칙을 따릅니다. 관리자 태그를 해제하려면:

```mcfunction
/tag "관리자닉네임" remove chestlog.admin
```

### 바닐라 기록의 정확도

**BE 안정판 Script API는 기본 상자 화면의 아이템 이동 행위자나 화면 닫힘을 직접 알려 주지 않습니다. 이 버전의 기록은 관찰·추정이며, 확정 감사 로그로 사용할 수 없습니다.**

- 상자 우클릭 직전 읽은 내용과 이후 **5틱 간격(정상 20 TPS에서 약 0.25초)**의 내용을 비교합니다. 최근 상호작용한 상자와 근처 플레이어 인벤토리 수량을 읽을 뿐, 아이템을 직접 이동·복제·삭제하지 않습니다.
- 같은 아이템의 상자 수량 증감과 플레이어 인벤토리의 정확히 반대인 증감이 일치하고, 후보가 한 명이며 최근 그 상자와 상호작용했다면 그 플레이어 이름 아래 **행위자 추정**으로 표시합니다. 우연히 호퍼 이동과 아이템 버리기/줍기 등이 겹쳐도 같은 변화가 나올 수 있으므로 이것도 증명은 아닙니다.
- 여러 사람이 같은 아이템을 동시에 옮기거나 수량이 맞지 않으면 특정 플레이어에게 배정하지 않고 **행위자 미확인** 변화로 남깁니다. 미확인 변화는 정상 플레이어별 목록과 분리합니다.
- 열기만 하거나 같은 상자 안에서 슬롯만 정리하여 아이템별 총량이 같으면 기록이 생기지 않습니다. **두 관찰 사이에 넣었다가 바로 같은 수량을 꺼내면 순변화가 0이므로 기록이 누락될 수 있습니다.** 모든 클릭의 개별 내역을 수집하지는 못합니다.
- 화면 닫힘을 감지하지 못하므로 최근 상호작용을 관찰 세션으로 취급합니다. 플레이어가 8블록 밖으로 벗어나거나 차원을 바꾸거나 나가거나 다른 상자를 사용하면 해당 플레이어 후보를 제외합니다. **마지막 우클릭부터 5분이 지나면 관찰이 종료**되므로 계속 기록하려면 닫고 다시 여세요. 화면을 닫아도 가까이 있으면 최대 5분간 변화 관찰이 계속될 수 있습니다.
- 동시에 최대 128개 상자를 관찰합니다. 초과 시 가장 먼저 관찰한 상자부터 관찰을 종료합니다. 서버 지연·재시작·언로드·관찰 종료 직전의 변화는 누락될 수 있습니다. 파괴·재설치·피스톤 이동을 정상 가져가기로 만들어 기록하지 않도록 관찰을 초기화합니다.
- 자동 장치, 명령어, 다른 애드온의 변경은 실제 플레이어 입출고와 완벽하게 구분할 수 없습니다. 대응하는 플레이어 변화가 없으면 미확인으로 표시합니다. 관찰 세션이 없는 상자는 감시하지 않습니다.
- 기록 저장 실패 시 바닐라 이용을 막거나 아이템을 되돌리지 않습니다. 다음 관찰에서 누적 수량 차이 저장을 재시도하므로 기록 시간은 실제 조작 시각과 달라질 수 있습니다.

1.0/1.1의 직접 처리한 기록은 **이전 직접 처리**로 구분하고, 과거 열람 요청 기록은 목록에서 숨깁니다. 이전 UUID를 유지하므로 월드에 저장된 기록과 소유권을 이어 사용합니다.

### 저장되는 정보와 조회

- 관찰 시각, 아이템 ID·수량, 이름·설명·손상도·인챈트·동적 속성 등의 아이템 정보, 추정 플레이어 이름/ID 또는 미확인 여부와 후보 이름을 저장합니다.
- 관리자 화면은 **플레이어별 넣기/가져가기 횟수 → 개인별 최신순 기록**으로 구성합니다. 시간은 UTC로 저장하고 **한국 표준시(KST)**로 표시합니다. 미확인 변화를 누군가의 입출고로 단정하지 마세요.
- 같은 큰 상자의 양쪽은 같은 기록을 사용합니다. 합치기/분리 이후에는 현재 좌표와 겹치는 이전 기록도 조회합니다. 철거·재설치한 같은 좌표에는 과거 기록이 남습니다.
- 로그와 소유권은 header UUID에 속한 **월드 동적 속성**에 저장합니다. 월드를 저장해야 디스크에 반영됩니다. 팩을 끄거나 UUID를 바꾼 동안의 행위는 기록하지 못합니다.
- 보존 한도는 좌표별 **최근 120건 또는 UTF-8 28,000바이트**, 기록 상자는 **최대 1,024개**입니다. 오래된 기록 삭제 건수를 보여 줍니다. 한도·저장 오류가 있어도 바닐라 상자 사용은 유지하며 새 기록은 누락될 수 있습니다.

### 소유자·폭발 보호

- 팩 활성화 후 플레이어가 설치한 일반 상자·덫 상자는 **설치자 또는 `chestlog.admin` 관리자만 파괴**할 수 있습니다. 크리에이티브도 동일합니다. 단, 관리자 조회 제스처는 파괴하지 않습니다.
- 과거 설치자를 알 수 없는 기존 상자는 **관리자만 파괴**할 수 있습니다. 먼저 여는 사람이 소유자가 되지 않습니다. 관리자가 좌클릭 조회 화면에서 **상자 소유자 지정**으로 등록하세요.
- 큰 상자는 양쪽 모두 본인 소유여야 일반 플레이어가 부술 수 있습니다. 혼합 소유/미등록이면 관리자만 파괴합니다. 관리자 소유자 지정은 양쪽을 함께 변경합니다.
- `beforeEvents.explosion`에 전달된 폭발의 파괴 대상에서 일반 상자·덫 상자를 제외합니다. 소유권 등록과 무관합니다. 대상 목록 확인에 실패하면 해당 폭발을 취소합니다. 주변 다른 블록과 엔티티 피해까지 막지는 않습니다.
- 피스톤 이동을 취소할 안정판 API가 없어 관련 원래/도착 좌표의 소유권과 관찰을 초기화합니다. 옮긴 뒤 관리자 소유자 재지정이 필요할 수 있으며 과거 로그는 원래 좌표에 남습니다.
- 소유권은 이름 대신 플레이어 ID로 비교합니다. 정상 파괴 후 소유권을 지우고, 재설치하면 새 설치자의 ID를 저장합니다.
- 엔더 상자·통·셜커 상자·상자 달린 이동수단은 지원하지 않습니다. 관리자 명령어와 다른 팩의 직접 블록 변경, 팩을 끈 동안의 변경은 보호 범위 밖입니다. 다른 보호 애드온과의 호환성은 별도 검증이 필요합니다.

## 나히아 개성

1.3.0에는 개성 10가지와 전용 기술 19개가 들어 있습니다. `.mcaddon`을 열어 행동 팩과 리소스 팩을 가져오고 월드에서 두 팩을 활성화하세요. 리소스 팩은 스테인의 검에 투명 배경의 256×256 도트 텍스처를 입힙니다.

응혈은 핏방울, 원포올은 청록색 번개, 폭파는 주황 섬광, 반랭반열은 얼음 결정과 열파, 대전은 황금색 전기, 창염은 푸른 불꽃, 올포원은 보랏빛 충격파로 표현했습니다. 발동 위치와 대상에 따라 오라, 궤적, 부채꼴 파동, 원형 충격파가 나타납니다.

기술은 Bedrock 전투에 맞춰 재구성했습니다. 1.3.0의 기술명과 효과는 나무위키 원문과 대조하지 못했습니다.

개성 아이템은 크리에이티브 인벤토리에서 이름으로 검색하거나 `/give @s <아이템 ID>`로 받을 수 있습니다. **아이템을 주 손에 들고 웅크리기 버튼을 누르면** 발동합니다. 응혈은 스테인의 검을 휘둘러 발동합니다. 스테인의 검은 제작대 가운데 열에 위에서부터 레드스톤 가루, 철 주괴, 막대기를 놓아서도 얻을 수 있습니다.

| 원포올 | 8초간 힘 II, 신속 II, 점프 강화 II를 얻습니다. 재사용 18초. | `mha:one_for_all` |

공격 개성으로 블록을 파괴하거나 불을 붙이지 않습니다. PvP가 꺼진 월드에서는 다른 플레이어에게 공격 개성과 말소 효과가 적용되지 않습니다.

### 개성별 기술

전용 기술 아이템을 주 손에 들고 웅크리기 버튼을 누릅니다. 아이템 이름 앞에는 개성 이름이 붙습니다. 원작 기술의 범위와 효과는 Bedrock 전투에 맞게 조정했습니다. 응혈 추적, 시야 말소, 근섬유 돌진은 개성에서 따온 추가 기술입니다.

| 개성 | 기술 | 효과 | 아이템 ID |

## 개발과 패키징

Node.js 24, npm, Python 3 환경에서 저장소 루트에서 실행합니다.

```sh
npm --cache /workspace/.npm-cache ci
npm run build
```

일반 PC에서는 `npm ci`도 가능합니다. `build`는 API 타입·매니페스트 검사, 자동 테스트, `.mcpack` 생성 및 ZIP 무결성 검사를 실행합니다. `@minecraft/server` npm 패키지는 선언 파일이며 게임 런타임이 아닙니다.

- `behavior_pack/scripts/main.js`: 바닐라 상자 상호작용 관찰 시작, 관리자 조회, 저장과 파괴 보호
- `behavior_pack/scripts/watcher.js`: 제한된 관찰 세션과 수량 변화·후보 비교
- `behavior_pack/scripts/core.js`: 아이템 스냅샷·변화·추정과 기록 보존 로직
- `tests/`: 모의 Bedrock API를 사용하는 자동 테스트
- `quirk_pack/`: 스테인의 검, 개성과 기술의 아이템·스크립트
- `quirk_resources/`: 스테인의 검 텍스처, 아이템 아틀라스, 기술 파티클
- `tools/`: 매니페스트 버전에 맞춰 `dist/ChestHistory-<버전>.mcpack`과 `dist/MHAQuirks-<버전>.mcaddon` 생성

## 검증 상태

클라우드에서 **타입·매니페스트 검사, 자동 테스트, 패키징**을 검증했습니다. **실제 Minecraft 게임 실행 검증은 아직 하지 않았습니다.** 운영 월드에 적용하기 전에 백업한 테스트 월드에서 다음을 확인하세요.

1. 가져오기·활성화 후 콘텐츠 로그에 오류가 없고 우클릭에서 바닐라 상자 화면이 나오는지 확인합니다. 빠른 이동·드래그·뚜껑·레드스톤도 확인합니다.
2. 관리자 웅크림+주 손 막대기+좌클릭만 조회되는지, 같은 조건의 우클릭이나 일반 플레이어에게는 조회 화면이 안 나오는지 확인합니다. 크리에이티브 조회로 상자가 파괴되지 않는지도 확인합니다.
3. 다이아몬드를 천천히 넣고 빼서 양쪽 수량과 추정 기록이 맞는지 확인합니다. 열기만 하기·슬롯 정리에는 기록이 없어야 합니다. 빠른 왕복 조작의 누락 가능성도 확인합니다.
4. 두 플레이어의 동시 조작과 호퍼/아이템 줍기가 겹칠 때 이름을 확정하지 않는지 확인합니다. 미확인 변화를 플레이어별 기록과 구분하세요.
5. 이름·인챈트·손상이 있는 장비, 큰 상자의 양쪽, 합치기/분리, 관찰 중 파괴·재설치·피스톤·차원 이동·로그아웃을 확인합니다.
6. 월드 저장·재시작 후 기록·소유권이 유지되고, 설치자/관리자만 파괴할 수 있는지 확인합니다. 기존 상자는 관리자 지정 전까지 일반 플레이어의 파괴를 거부해야 합니다.
7. 월드에서 사용할 TNT·크리퍼·침대·리스폰 정박기 등의 폭발과 실제 모바일·게임패드의 공격 동작을 시험합니다. 이 이벤트로 전달되지 않는 피해/타 팩 변경은 별도 검증이 필요합니다.
